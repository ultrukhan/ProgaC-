1. Привид порожнечі: ArgumentNullException: Value cannot be null
Як виглядає: Програма крашиться з червоним текстом у консолі, вказуючи на рядок, де ти створюєш new XAttribute(...) або робиш вибірку select new {...}.
Чому виникає: LINQ намагається взяти дані з XML-тегу, але не знаходить його, тому повертає null. А XAttribute не вміє створюватися з null.
Де шукати проблему:

Регістр букв: Ти написав Element("Category"), а в XML файлі тег називається <category> з маленької. XML максимально чутливий до регістру.

Різні назви: Ти написав Element("Name"), а в XML це <DishName>.

Відсутній тег: У твоєму xml-файлі (наприклад, у папці bin/Debug/net8.0/) в одному із записів ти випадково видалив або забув дописати потрібний тег.
Як виправити: Відкрити XML-файл, з якого читаються дані, і звірити кожну букву назви тегу з тим, що ти написав у коді в методі .Element("...").


 2. Абракадабра замість даних: System.Linq.Enumerable...
Як виглядає: Код працює, не падає, але у згенерованому XML-файлі замість числа або слова ти бачиш довжелезний системний рядок System.Linq.Enumerable+SelectIListIterator....
Чому виникає: Ти спробував запхати цілий список (колекцію) або групу в один текстовий атрибут XAttribute.
Де шукати проблему: Там, де ти формуєш XML-дерево після group by.
Як виправити: * Якщо ти згрупував дані (group d by d.Category into dc), і хочеш вивести назву категорії, переконайся, що ти передаєш ключ: new XAttribute("Name", dc.Key).

Якщо ти випадково передав у атрибут LINQ-запит (from x in... select x), зміни архітектуру: списки мають бути вкладеними тегами new XElement(...), а не атрибутами.



3. Логічна пастка: Count() замість Sum()
Як виглядає: Код працює ідеально, XML генерується, але цифри не сходяться (наприклад, дохід правильний, а кількість "5" замість "11").
Чому виникає: Неуважне читання умови завдання (особливо Завдання Б).
Де шукати проблему: В агрегатних функціях let або при створенні XAttribute зі статистикою.
Як виправити (запам'ятай правило):

Якщо просять знайти кількість замовлень / чеків / транзакцій ➔ використовуй dg.Count().

Якщо просять знайти кількість проданих порцій / заброньованих ночей / куплених товарів (тобто в XML є окремий тег <Nights> чи <NumOf>) ➔ використовуй виключно суму: dg.Sum(x => x.NumOf).



4. Помилка формату: FormatException при читанні XML
Як виглядає: Програма крашиться ще на етапі запуску або при спробі зробити кастинг (DateTime) чи (double).
Чому виникає: Дані в XML-файлі записані у форматі, який C# не може автоматично розпізнати.
Де шукати проблему: У стартових XML-файлах (фікстурах або файлах на диску).
Як виправити:

Дати: Завжди пиши дати строго у міжнародному форматі через дефіс: РРРР-ММ-ДД (наприклад, 2026-05-20). Жодних крапок чи скісних ліній.

Дробові числа (Ціни/Знижки): Завжди використовуй крапку, а не кому! <Price>150.5</Price>, а не <Price>150,5</Price>.



5. Загублений let (Математика в кінці)
Як виглядає: Ти намагаєшся знайти максимальну суму або відфільтрувати за доходом, але компілятор підкреслює код червоним або не дає звернутися до потрібного поля.
Чому виникає: Ти намагаєшся виконати умову where або знайти .Max() до того, як LINQ фізично порахував ці значення для кожної групи.
Як виправити: Спочатку згрупуй (group ... by ... into g), потім створи змінну через let (let rev = g.Sum(...)), і тільки після цього пиши where rev >= minRev або orderby rev descending.
